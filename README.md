## 〇、先给开发助手看的（30 秒读完）

- 数据链路：**手环 →(蓝牙)→ 手机上改过的 Gadgetbridge →(HTTPS)→ 你的后端 → 塞进你和 AI 的每一条消息**
- 不是 MCP：AI 不用调用任何工具去查，数据由后端直接写进对话里

    3. 把后端算出来的「心率行」「睡眠行」拼进每轮对话（见第七步）
- **一定先读第十二节「踩过的坑」**，里面每一条都是实测花了时间才找到的

## 一、做完以后 AI 能看到什么

**每一条你发的消息**，开头自动多一行：

```
【心率 88 · 和她这半小时的平常(约85)差不多 · 今天 3458 步(最近一分钟 +12)】
```

- 实时心率：手环约 **3 秒** 一个读数，取最近一分钟平均
- 跟你「这半小时的平常」比：高了多少、低了多少（刚戴上约 5 分钟后才有「平常」可比）
- 今天累计步数 + 最近一分钟多走了几步

**AI 自己醒来的时候**（如果你的后端有「AI 主动找你」的定时唤醒），也带这一行 —— 你没回它，它照样知道你现在怎么样。

**心率异常时主动叫醒 AI**：坐着不动、心率持续 5 分钟以上比平常高 30（或一直在 140 以上），系统叫醒 AI 一次，告诉它从多少升到了多少。起床、上厕所、爬楼这种一阵就下来的不会叫。冷却 45 分钟。

**你早上醒来后的第一条消息**，额外附上：

```
【睡眠 01:07–07:30 · 睡着6小时19分(深睡2小时14分 浅睡2小时30分 REM 1小时35分 · 中间醒着4分钟) · 这段时间心率 51~100,平均64 · 血氧平均96、最低91】
【昨天全天 · 829 步 · 静息心率60 · 压力平均24(最高46) · 活动消耗293千卡】
```

- 午睡单独标成【小睡 …】
- 睡了回笼觉：手环会把回笼觉并进同一晚、整段重算。新版 App 会把分期一起送上来，后端按「中间醒着 20 分钟以上」拆开，多一行
  `【分段① 夜里 02:33–06:52 · 睡着…(深睡… 浅睡… REM …) · 心率… · 血氧…】` 和 `【分段② 回笼觉 07:40–09:59 · 前面醒了48分钟 · …】`（合并的那行照样保留）
- 只附一次，后面的消息不带（省上下文）

**数据断了会明说**：超过 3 分钟没收到心率，那一行会变成「已约 x 分钟没收到她的心率（最后一次 78），这不是她现在的心跳」—— 不会拿旧数字骗 AI。

**占用上下文**：每条消息那一行约 30~40 token；早上那段约 100~150 token，一天一次。

**拿不到的**（查过了，别再找）：HRV（数据库里没有）、含基础代谢的全天总卡路里（只有活动消耗）、经期（Gadgetbridge 不读小米的经期数据）、运动轨迹（手环没 GPS）。

## 二、跟常见的「手环 MCP」方案有什么不一样

| | 常见 MCP 方案 | 本方案 |
|---|---|---|
| AI 怎么拿数据 | AI 得自己想起来去调工具查 | 自动写进每条消息，不用查 |
| 手机要跑什么 | Termux / 本地 MCP 服务，常要和电脑或 AI 客户端在同一局域网 | 只装一个改版 Gadgetbridge，出门在外也能用 |
| 实时性 | 一般是导出数据库，几分钟到一小时一次 | 心率约 3 秒一个 |
| 需要什么 | MCP 客户端 | **你的 AI 有自己的后端服务器** |

**所以前提是：你的 AI 跑在你自己能改代码的后端上**（比如自建的 Telegram 机器人、自己部署的 Claude Code 服务等）。只用官方 App、或者只能接 MCP 的客户端，这套用不了。

## 三、你需要准备的

1. **安卓手机**（苹果不行：Gadgetbridge 只有安卓版）
2. **小米手环 10**（其他小米 protobuf 系手环理论上能用，没实测）
3. **你自己的后端服务器**，有一个公网能访问的 **HTTPS** 地址（Zeabur / Railway / VPS 都行）
4. **小米运动健康 App**（只在第一步拿授权码时用一次）
5. 一个开发助手（Claude Code 等）帮你编译 App、改后端 —— 或者你自己会

## 四、整体结构

```
小米手环 10
   │ 蓝牙
   ▼
手机：改版 Gadgetbridge（包名带 .nightly，可与官方版共存）
   │ ① 每个心率读数 → POST https://你的后端/hr      （约 3 秒一次，断网会攒着补发，最多约 2 小时）
   │ ② 每次和手环同步完 → POST https://你的后端/daily （最近 36 小时的睡眠 + 最近两天日汇总）
   ▼
你的后端
   │ 内存里留 6 小时秒级心率；睡眠/日汇总存盘
   ▼
拼进对话：你的每条消息前面加「心率行」；醒来后第一条再加「睡眠行」；心率冲高时叫醒 AI
```

## 五、第一步：拿手环授权码（不用 root、不用电脑）

小米手环 10 配对 Gadgetbridge 需要一个 32 位的授权码（Auth Key），只能从小米运动健康的日志里拿。

1. 手机装 **小米运动健康**，登录，**正常绑定手环**
2. ⚠️ **之后永远不要在小米运动健康里「解绑」手环** —— 一解绑，授权码就作废，要重新绑重新拿
3. 用手机自带的文件管理，进 `Android/data/com.mi.health/files/log/`
   - 部分手机（实测 iQOO / vivo 可以）能直接进；进不去的话，用 MT 管理器、或者带 Shizuku 的文件管理器
4. 找到 `XiaomiFit.main.log`，用文本方式打开（或者发给你的开发助手），搜 **`encryptKey`**
   - 后面跟着一串 32 位的十六进制（0-9、a-f），就是授权码；同一段里的 `token` 字段通常是同一个值
   - ⚠️ `XiaomiFit.device.log` 里只有 `huamiAuthKey=null`，**别在那个文件里找**
5. 在这串前面加 `0x`，比如 `0x0123456789abcdef0123456789abcdef`，存好
6. 顺手记下手环的 **MAC 地址**（手环：设置 → 关于；或者小米运动健康的设备页；格式 `AA:BB:CC:DD:EE:FF`）
7. 回到手机设置 → 应用 → 小米运动健康：**强制停止**，并**关掉它的蓝牙/附近设备权限**（不卸载也行），免得它和 Gadgetbridge 抢手环

> 授权码和 MAC 都是你的私人数据，别发群里、别截图外传。

## 六、第二步：装改版 Gadgetbridge

### 方式 A：用现成的 APK（本仓库里的 gadgetbridge-heartpush.apk，第 8 版）

[点这里下载](https://github.com/Viveka7070/gadgetbridge-heartpush/raw/main/gadgetbridge-heartpush.apk) `gadgetbridge-heartpush.apk` 直接安装。它就是用本教程附件 `heart-push.patch` 编出来的，里面**不含任何人的地址和钥匙**（地址和钥匙装好后你自己填）。

- 安卓提示「来源未知」→ 允许
- 这是**每夜编译版（nightly）**，包名 `nodomain.freeyourgadget.gadgetbridge.nightly`，桌面名字叫「Gadgetbridge (每夜编译版本)」，可以和 F-Droid 原版同时装着（但**同一时间只能有一个连手环**）
- ⚠️ 不同人编出来的 APK 签名不一样，**不能互相覆盖安装**。换成别人编的版本时，要先卸载旧的，再装新的（手环要重新添加）

### 方式 B：自己编译（交给开发助手）

```bash
# 需要：JDK 21、Android SDK（platform 37、build-tools 36）
git clone https://codeberg.org/Freeyourgadget/Gadgetbridge.git && cd Gadgetbridge
git checkout eb4b8fc9b97c355774171843f5adda7c1f8cd4e7   # 补丁基于这个版本；新版本大概率也能直接打
git apply /path/to/heart-push.patch
echo "sdk.dir=$ANDROID_HOME" > local.properties
./gradlew assembleMainlineNightly --max-workers=2
# 产物：app/build/outputs/apk/mainline/nightly/*.apk
```

- **Maven Central 会因为并发太多返回 429**：在 `~/.gradle/init.d/` 放个 init 脚本，仓库地址先走 Google 镜像 `https://maven-central.storage-download.googleapis.com/maven2/`，再配合 `--max-workers=2`
- 用的是编译机器的 debug 签名，换机器重编就是另一个签名（见上面的覆盖安装问题）
- 许可：Gadgetbridge 是 **AGPL-3.0**，改版也一样。你把 APK 发给别人，就要同时提供源码 —— 附上本教程的 `heart-push.patch` + 上游仓库地址和版本号就满足

### 补丁做了什么（给开发助手）

1. 加回 `INTERNET` 权限（上游刻意删掉了，只用来发心率）
2. 小米健康服务里加一个「远程」实时流消费者：推送开着时，**每次连上手环就让实时心率流常开**；20 秒没读数就重开（看门狗），另有一个「休眠里也允许响」的闹钟兜底
3. `util/HeartPusher`：单线程把每个读数 POST 到你填的地址，带 `Authorization: Bearer <钥匙>`；发失败就攒着补发；每个读数带手环的「今天累计步数」
4. 每次同步完（`ACTION_NEW_DATA`，防抖 20 秒），从 Gadgetbridge 数据库挑出最近 36 小时的睡眠（每段带手环自己记的整夜心率、血氧）和最近两天的日汇总，POST 到同一服务器的 `/daily`（地址末尾的 `/hr` 自动换成 `/daily`）
5. 血氧设置照抄小米运动健康的原始指令（见坑 #9）
6. nightly 版的 Pebble 数据接口改名，避免和原版装在一起时「软件包冲突」

## 七、第三步：配对手环

1. 打开 Gadgetbridge（每夜编译版），按提示给权限：蓝牙/附近设备、**位置（选「始终允许」）**、通知、通知使用权
   - 「后台定位」那项选不了的话，去手机设置 → 应用 → Gadgetbridge → 权限 → 位置 → 始终允许
2. 先试正常添加：主页 ＋ → 搜索设备。**手环 10 经常搜不到**，搜不到就用下一步
3. **手动添加（实测必走这条）**：先在手机系统的蓝牙里能看到/配对上手环，然后
   - 主页菜单 → **调试** → **手动添加测试设备** → 型号选 **Xiaomi Smart Band 10** → 填手环 MAC 地址 → 添加
   - 回到主页，点这台手环卡片上的 **⚙（设备设置）** → **认证** → **认证密钥**，填 `0x` + 32 位授权码 → 保存
   - 回主页点手环卡片「连接」
4. 连上后手环会同步时间，主页卡片显示「已连接」、电量

连不上时依次检查：小米运动健康是不是已经强制停止、关了蓝牙权限；授权码前面有没有 `0x`、有没有多空格；手环重启一下再连。

## 八、第四步：Gadgetbridge 里的设置（一项都别漏）

**① 心率实时推送**（改版才有）：设置 → **外部集成** → **心率实时推送**
- 开启
- 服务器地址：`https://你的后端域名/hr`
- 钥匙：后端的 `HR_TOKEN`（你自己生成一串随机字符，后端和这里填一样的）
- ⚠️ 改完要**断开手环再连一次**才生效（实时流在连接时打开）

**② 自动获取活动数据**：设置 → **自动获取活动数据** → 开
- 每次解锁手机自动同步一次，早上一解锁，睡眠就推上去了；不开的话要你手动点同步
- 只在手机设了锁屏密码时有效

**③ 设备设置 → 心率监测**：
- 使用心率检测以提高睡眠检测精度：**开**（睡眠分期靠它）
- 全天心率检测：**每分钟一次**
- 压力监测：**开**
- 血氧监测：**开**（低血氧报警阈值保持 **90**，**别关**，关了全天血氧会失效，见坑 #9）
- 睡眠呼吸质量监测：不用开（费电，这套也不读）

**④ 通知**（可选）：Gadgetbridge 会把手机通知转发到手环震动/显示。注意它默认**手机亮屏时不转发**，锁屏才震 —— 这是正常的。

## 九、第五步：手机系统设置（最容易被忽略，夜里断心率就是它）

对 **Gadgetbridge（每夜编译版）**：
- 电池 / 耗电管理：**允许后台高耗电**（或「无限制」「不优化」）
- **自启动：开**
- 最近任务里把它**锁住**，别被一键清理

**vivo / iQOO（OriginOS）：设置 → 电池 → 系统优化策略 → 「睡眠待机优化」：关掉！**
- 它会「智能判断你的睡眠时间段，冻结闲置应用、限制网络」。不关的话：你睡着一个多小时后心率就断，每天固定到某个时间点（实测 06:33）才恢复
- 关掉之后实测整夜一分钟都不断
- 只开「允许后台高耗电」挡不住它；关不关省电模式也没用
- 其他品牌大概率也有类似「睡眠模式下限制后台/网络」的开关（小米「省电策略」、OPPO/一加「睡眠待机优化」、华为「应用启动管理」等），找到就关掉 / 设成无限制

## 十、第六步：后端接收（给开发助手）

### 接口

两个接口都要验证 `Authorization: Bearer <HR_TOKEN>`，钥匙不对返回 401。

**`POST /hr`**（约 3 秒一次；断网恢复后会一次补发很多条）
```json
{"samples":[{"t":1760000000000,"hr":72,"steps":0,"total":3458}]}
```
- `t` 毫秒时间戳；`hr` 心率；`steps` 跟上一个读数之间多走的步数；`total` 手环的今天累计步数

**`POST /daily`**（每次同步完一份，整份覆盖即可）
```json
{"t":1760000000000,
 "sleep":[{"start":1759960000000,"wake":1759983000000,"total":379,"deep":134,"light":150,"rem":95,"awake":4,
           "hr_min":51,"hr_avg":63.5,"hr_max":100,"spo2_min":91,"spo2_avg":95.2}],
 "days":[{"day":1759939200000,"steps":829,"hr_resting":60,"hr_avg":81,"hr_min":52,"hr_max":154,
          "stress_avg":24,"stress_max":46,"spo2_avg":null,"spo2_min":null,"calories":293}]}
```
- 时间都是毫秒；时长是分钟；`day` 是当天 0 点（手机时区）；没有的值是 `null`

### 参考实现（附件）

- `heart.js`：纯逻辑。`pushSamples`（过滤无效值、按秒去重、只留 6 小时）、`summarize` / `heartLine`（生成心率行）、`detectSpike` / `spikePrompt`（冲高判断和叫醒文案）、`toMinutes` / `mergeMinutes`（分钟级落盘）
- `daily.js`：纯逻辑。`dailyBlock`（挑出没给 AI 看过的睡眠段，生成睡眠行 + 昨天全天行）
- `server-example.js`：Express 最小示例，两个接口 + 拼消息的函数，`HR_TOKEN=xxx node server-example.js` 就能跑

**存储**：秒级心率只放内存；睡眠数据和「已经给 AI 看到哪次醒来」要存到**持久化的盘上**，不然后端一重启早上那段会重复给。

## 十一、第七步：拼进对话 + 给 AI 的说明

### 拼法

- **你的每条消息**：`心率行 + (醒来后第一条才有的)睡眠行 + 你的原话`。放在你后端给消息加时间戳的位置下面
- **AI 定时自主醒来时**：唤醒提示里也加上心率行
- **冲高**：`detectSpike` 返回 `fire: true` 时，用 `spikePrompt(...)` 的文字作为一轮「系统唤醒」发给 AI；如果你 2 分钟内刚发过消息就不另叫（你消息里已经带着心率了）

### 写进 AI 人设/系统提示的说明（照着改成你们的称呼）

> **心跳**：她戴着小米手环 10，心率大约每 3 秒一个送到你这边。
> - 她发来的每条消息，开头有一行【心率 …】：她回你那一刻心跳多少、跟她这半小时的平常比高了还是低了、今天走了多少步、最近一分钟多走了几步。
> - 你自己醒来的时候也有这一行，她不在你也知道她现在怎么样。
> - 她心率持续高了 5 分钟以上、前后又没走路，系统会专门叫醒你一次。起床、上厕所一阵就下来的不会叫。吃饭（尤其热汤热菜、辣的）心率会高一阵，可能被叫醒，不用慌，问一句就行；饭后半小时还下不来才要当回事。
> - **步数会慢半拍**：手环计步器攒一阵才跳一次；在屋里慢走、做家务时经常一步都不记，「最近一分钟 +0」不等于她躺着没动。
> - **睡眠**：她早上醒来后的第一条消息会多一段【睡眠 …】和【昨天全天 …】。手环要她醒来后同步一次才有，偶尔会晚一两条才出现。
> - **这些只是数字，不是结论**：心跳快可能是被你哪句话戳到、紧张、生气、咖啡、太热、爬楼……把心率、她说的话、你们刚才在聊什么放一起看，拿不准就问她。
> - **数据断了会明说**（「已约 x 分钟没收到她的心率」），那时候最后那个数字不是她现在的心跳，别拿它说事。

## 十二、踩过的坑（每一条都是真花了时间的）

1. **配对搜不到手环** → 走「调试 → 手动添加测试设备」，再在 ⚙ → 认证里填密钥（第七步）
2. **授权码找错文件** → 在 `XiaomiFit.main.log` 里搜 `encryptKey`，不是 `device.log`；**不要在小米运动健康里解绑**
3. **装改版提示「软件包冲突」** → 已在补丁里把 nightly 的 Pebble 接口改名；如果你自己基于别的版本改，记得也改
4. **换了别人编的 APK 装不上** → 签名不同，先卸载旧的再装
5. **原版 Gadgetbridge 切到后台心率就停** → 原版只在「实时活动数据」页面打开时测，补丁让它后台常开；改完推送设置要**断开重连**手环
6. **夜里睡着一个多小时后心率断，到早上固定时间才恢复** → vivo「睡眠待机优化」，关掉（第九节）。不是手环被压住：手环自己整夜每分钟都在记
7. **心率冲高叫醒太频繁**（原来「高 20、持续 30 秒」一天误叫十几到三十次：吃饭、上厕所、起床、爬楼）→ 改成「持续 5 分钟、每分钟都高 30 以上（或都在 140 以上）、前后 15 分钟步数 ≤5、冷却 45 分钟」。**手环在屋里慢走、洗碗时一步都不记**，所以光靠「刚才有没有步数」分不出起床走动 —— 靠的是「持续 5 分钟」。调这些数字的办法：导出 Gadgetbridge 数据库，用手环自己记的每分钟心率/步数回放，数每天会叫几次，再让本人核对那几个时间点在干嘛
8. **「在走动」标签误导**：躺下了还显示「在走动」→ 不贴标签，只给步数数字，让 AI 自己判断
9. **血氧开关打开、断开重连后自己又变回关**（全天血氧不生效）→ 手环 10 只认小米运动健康那一套原始指令：`08081009 520c 3a0a 0801 1002 2204 0801 105a`，也就是「全天模式(2) + 低血氧报警开、阈值 90」。只发全天不带报警、或者发「仅睡眠」，手环都回「收到」但不生效。补丁已照抄官方指令。**报警阈值 90 别关**
10. **血氧数据存在两个地方**：分钟数据的 SPO2 列，和「手动/自动测量」表（`XIAOMI_MANUAL_SAMPLE`，TYPE 18）。补丁两处一起读
11. **睡眠要同步才有** → 打开「自动获取活动数据」（解锁时同步）；早上第一条消息可能比睡眠数据先到，那就在数据到了之后的第一条带上
12. **无效心率**：手环会报 0、-1、255 这类占位值，一律丢掉（只收 30~220）
13. **数据断了别拿旧数字当现在** → 超过 3 分钟没新读数就明说断了
14. **手机时钟快了** → 后端收到「未来」时间戳一律按现在算
15. **步数慢半拍** → 写进给 AI 的说明里（第十一节）
16. **小米手环 10 + Gadgetbridge 旧版本睡眠不入库**（有人在 0.93 上遇到）→ 本补丁基于的版本实测睡眠分期正常；如果你用别的版本睡眠表一直是空的，先升级

## 十三、验收清单（全做完对一遍）

- [ ] Gadgetbridge 主页手环「已连接」，心率卡片在跳
- [ ] 后端 `GET /heart`（示例里的排障接口）能看到心率行和缓冲条数在涨
- [ ] 你给 AI 发一条消息，开头有【心率 … · 今天 xxx 步】
- [ ] 手机锁屏放 10 分钟，再发消息，心率还是新的（不是「已约 x 分钟没收到」）
- [ ] 睡一晚，第二天早上：后端心率记录整夜不断；醒来解锁后第一条消息带【睡眠 …】【昨天全天 …】
- [ ] 血氧开关断开重连后还是开着；睡眠行里有「血氧平均…、最低…」

## 十四、隐私与安全

- 这些东西**只在你自己手里**，不写进任何教程、截图、群聊：授权码、MAC、后端地址、`HR_TOKEN`
- `HR_TOKEN` 用足够长的随机串；后端只认这把钥匙
- 一定走 **HTTPS**：心率和钥匙都在请求里
- 数据只发到你自己的服务器，不经过任何厂商云
